# 프론트엔드 (React + Vite)

부품별 상태와 점검 우선순위를 보여 주는 정비 의사결정 대시보드입니다.

## 실행

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

- Node.js 20 이상이 필요합니다. Vite 7은 Node 20.19 이상이 필요해서 Vite 6으로 고정해 두었습니다.
- `/api`로 시작하는 요청은 `vite.config.js`의 proxy 설정으로 백엔드(http://localhost:8000)에 전달됩니다. 백엔드도 함께 켜 두어야 데이터가 보입니다.

## 지금 만들어진 것

| 파일 | 내용 |
| --- | --- |
| `src/App.jsx` | 첫 화면. 백엔드 연결 상태와 부품 카드 4개 |
| `src/api/client.js` | 백엔드 호출 함수 (`fetchHealth`, `fetchComponents`) |
| `src/components/ComponentCard.jsx` | 부품 하나의 등급 정의를 보여 주는 카드 |
| `src/index.css` | 기본 스타일 |

화면이 "백엔드: 연결됨"과 부품 카드 4개를 보여 주면 개발 환경이 정상입니다.

## 할 일

1. **화면 설계**: 어떤 정보를 어떤 순서로 보여 줄지 정합니다. 정비 담당자가 처음 보고 "무엇부터 점검할지" 바로 알 수 있어야 합니다.
2. **사이클 선택**: 데모용으로 데이터셋의 사이클을 고르는 UI를 만듭니다 (백엔드 `GET /api/cycles`).
3. **부품별 상태 표시**: 예측 등급과 확률을 카드에 보여 줍니다. 정상 / 주의 / 위험을 색으로 구분합니다 (`GET /api/cycles/{cycle}/diagnosis`).
4. **점검 우선순위**: 우선순위 목록이나 표를 만듭니다 (`GET /api/cycles/{cycle}/priority`).
5. **차트** (선택): 센서 추이나 등급별 분포 그래프. 라이브러리는 담당자가 고릅니다 (예: Recharts).
6. **오류·로딩 상태**: 백엔드가 꺼져 있거나 응답이 느릴 때의 화면을 만듭니다.

API 경로와 응답 형식은 아직 초안입니다. [backend/README.md](../backend/README.md)의 "API 초안"을 보고 백엔드 담당과 맞춰 주세요. 백엔드가 준비되기 전에는 응답 예시를 가짜 데이터로 넣고 화면부터 만들 수 있습니다.

## 화면에 쓸 용어

| 부품 | 등급 (정상 → 고장 직전) |
| --- | --- |
| 냉각기 | 100% 정상 효율 → 20% 효율 저하 → 3% 고장 직전 |
| 밸브 | 100% 정상 응답 → 90% 약간 지연 → 80% 심한 지연 → 73% 고장 직전 |
| 펌프 | 0 누유 없음 → 1 약한 누유 → 2 심한 누유 |
| 축압기 | 130bar 정상 압력 → 115bar 약간 저하 → 100bar 심한 저하 → 90bar 고장 직전 |

같은 정보를 `GET /api/components`로도 받을 수 있습니다.
